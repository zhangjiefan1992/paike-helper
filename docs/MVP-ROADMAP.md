# MVP 定义 & 实现路径

> 版本：v1.0
> 日期：2026-05-15
> 核心检验标准：你老婆连续用 1 周不回退到备忘录

---

## 一、MVP 到底是什么

MVP 不是"功能列表都做了"。MVP 是：

**一个教练愿意从备忘录切过来、并且截图发给会员的排课工具。**

验证成功的标志（全部满足才算）：
1. ✅ 她连续用 1 周没回退到备忘录
2. ✅ 她主动截图课表发给会员确认排课
3. ✅ 她觉得查会员历史比翻聊天记录方便
4. ✅ 她课后愿意花 30 秒在这里记录而不是微信笔记

**做不到任何一条 → MVP 没过，不进入下一阶段。**

---

## 二、为什么当前版本还不是 MVP

当前状态：功能基本完整，但**体验不够让人"切换"**。

| 维度 | 备忘录 | 当前排课助手 | 差距 |
|------|--------|------------|------|
| 录课速度 | 5秒（打字"张三周一3点普拉提"） | 30秒+（选日期→选时间→选会员→选类型） | **慢 6 倍** |
| 看课表 | 一屏文本列表 | 周视图，但视觉普通 | 好一点，但不够"哇" |
| 查历史 | 翻聊天记录/备忘录搜索 | 会员详情有时间轴 | 有优势，但时间轴需打磨 |
| 课后记录 | 微信笔记/纸质 | 备注文本框 | 没有明显优势 |

**关键洞察：当前 App 在"录入"上比备忘录还慢，在"展示"上还不够惊艳。录入和展示两头都没赢。**

## 三、MVP 分两步走

### Step 1：打磨极致体验（无 AI，纯前端）

> 目标：录入不比备忘录慢太多 + 展示远超备忘录
> 周期：1-2 周
> 验证：给老婆用，观察她用不用

#### 1.1 周视图打磨到「截图级好看」 — 最高优先级

这是教练每天打开 App 看到的第一个画面，也是截图发给会员的东西。

**当前问题：**
- 视觉平庸，像后台管理系统而不是教练的个人品牌
- 信息密度不够（缺地点、缺会员数量提示）
- 不适合截图分享（没有品牌感）

**要做到：**
- [ ] 一眼看全周：时间、会员名、课程类型、地点、状态色
- [ ] 视觉精致：参考 Cal.com / Apple Calendar 的卡片质感
- [ ] 截图友好：合适的边距和比例，角落轻品牌水印
- [ ] 今日高亮：当天列明显突出，扫一眼知道"今天有什么课"
- [ ] 周统计摘要：顶部一行"本周 12 节课 · 8 位会员"

**参考对标：** Calendly 的预约页（干净）、Notion Calendar（信息密度）、Lululemon App（品牌感）

#### 1.2 录课表单极简化

**当前问题：** 7 个字段逐一填写，操作太多。

**要做到：**
- [ ] 智能默认值：日期默认今天/明天，时间默认下一个空闲时段
- [ ] 常用组合记忆："张三+普拉提+xx馆"上次选过 → 本次自动填入
- [ ] 最少必填：只需选「会员」和「时间」，其他全有默认值
- [ ] 快速重复：长按已有课程 →"复制到下周同一时间"

**目标：** 已有会员的排课 3 步完成（选会员→选时间→保存），< 10 秒。

#### 1.3 会员详情增强

**当前问题：** 只有"总课时"和"已完成"两个数字，历史记录太简陋。

**要做到：**
- [ ] 上次上课日期 + 距今天数（"上次：5/13，2天前"）
- [ ] 最近 5 次课程摘要卡片（类型+重点+备注预览）
- [ ] 训练分布饼图或标签云（一眼看出练什么最多）
- [ ] 备注高亮：如果有"膝盖不适""腰伤"等关键词，醒目提示

**价值：** 教练课前打开会员详情，3 秒回忆"上次练了什么"。这是备忘录做不到的。

#### 1.4 课后快速记录

**当前问题：** 备注是普通文本框，没有引导，教练不知道记什么。

**要做到：**
- [ ] 课程完成后自动弹出"快速记录"入口（不强制）
- [ ] 预设快捷标签："进步明显""需要注意""状态一般""配合很好"
- [ ] 一行文本框 + 快捷标签 = 5 秒完成一次记录
- [ ] 记录后即时可见（会员详情时间轴里出现）

**目标：** 快速记录 < 30 秒，比打开微信笔记还快。

---

### Step 2：接入 AI（需要服务端）

> 目标：录入速度超过备忘录 — 这是真正的 game changer
> 前提：Step 1 通过验证（老婆真的在用）
> 周期：2-3 周

#### 2.1 服务端部署

- [ ] Fastify 服务端骨架（已有设计，见 SERVER-DESIGN.md）
- [ ] JWT 认证 + 微信登录
- [ ] DeepSeek API 接入（成本最优的 LLM）
- [ ] 基础健康检查 + 日志

#### 2.2 自然语言录课

```
教练输入："明天3点张三普拉提，周五同一时间李四瑜伽"
    → AI 解析
    → 返回 2 张课程预览卡片
    → 教练确认 → 一键保存
```

- [ ] POST /api/v1/ai/parse-text — 文本 → 结构化课程
- [ ] 前端"快速录课"入口 — 一个输入框 + 确认预览
- [ ] 批量解析能力 — 一段话多节课

#### 2.3 语音录课/速记

- [ ] 前端语音录制 → 发送音频到服务端
- [ ] 服务端 ASR（语音转文字）→ 复用 parse-text 管道
- [ ] 课后速记场景 — 语音 → 自动填入课程备注

#### 2.4 AI 课前建议卡 V1

- [ ] POST /api/v1/ai/lesson-plan — 基于历史数据生成建议
- [ ] 纯数据驱动（训练分布、注意事项、会员备注汇总）
- [ ] 会员详情页入口 →"生成课前参考"

## 四、明确不做的事情（MVP 阶段）

以下功能有价值但**不在 MVP 范围内**，避免分散精力：

| 不做 | 原因 |
|------|------|
| 体态评估模块 | 需要照片存储+服务端，等服务端稳定后做 |
| 多主题切换 | 先把一套主题做到极致，再加选择 |
| 统计报表页 | 会员详情的简单统计够用，独立统计页延后 |
| 数据导入导出 | 不是切换决策因素 |
| PWA / 离线缓存 | 当前阶段网络依赖低（本地存储） |
| 会员端展示 | 教练自用工具，不做 C 端 |
| 微信公众号对话 | 小程序 + H5 足够，不加新载体 |
| 云同步 | MVP 用本地存储，云同步是付费功能 |

## 五、执行顺序（具体到任务）

```
Week 1 ─────────────────────────────────────
  ▸ 周视图 UI 重新设计+实现（最重要，这是门面）
  ▸ 录课表单智能默认值+极简化
  
Week 2 ─────────────────────────────────────
  ▸ 会员详情增强（历史摘要、训练分布）
  ▸ 课后快速记录体验优化
  ▸ 整体视觉打磨（统一色彩、间距、动效）

── 交付给老婆使用，观察 1 周 ──

Week 3 ─────────────────────────────────────
  ▸ 收集反馈，修复体验问题
  ▸ 如果 Step 1 验证通过 → 开始服务端

Week 4-5 ───────────────────────────────────
  ▸ 服务端部署 + AI 接入
  ▸ 自然语言录课 + 语音录课
  ▸ 课前建议卡 V1

── 拉 3-5 个教练内测 ──
```

## 六、每个阶段的「完成标准」

### Step 1 完成标准

| 检查项 | 标准 |
|--------|------|
| 周视图截图 | 发到微信群里有人问"这是什么 App" |
| 录课速度 | 已有会员排课 < 10 秒（3 步：选人→选时间→保存） |
| 会员详情 | 打开 3 秒内知道"上次练了什么、要注意什么" |
| 课后记录 | 30 秒内完成，比打开微信笔记快 |
| 整体感受 | 老婆说"比备忘录好用" |

### Step 2 完成标准

| 检查项 | 标准 |
|--------|------|
| 自然语言录课 | "明天3点张三普拉提" → 正确解析率 > 90% |
| 批量录课 | 一段话排 3-5 节课，全部正确 |
| 语音速记 | 课后说一句话 → 正确记录到对应课程 |
| 课前建议 | 基于真实数据生成，教练觉得"有点用" |
| 成本 | 单用户月 AI 成本 < ¥3 |

## 七、风险与缓解

| 风险 | 概率 | 缓解 |
|------|------|------|
| 周视图做不到"截图级好看" | 中 | 参考成熟设计系统，必要时请设计师出图 |
| 老婆用了一周回退到备忘录 | 中 | 认真做用户访谈，找出真正的卡点 |
| AI 解析准确率不够 | 低 | DeepSeek 对中文理解好；兜底：解析失败回退到手动表单 |
| 微信审核卡 AI 功能 | 低 | AI 交互包装为"智能表单"，不做聊天框 |
| AI 成本超预期 | 低 | DeepSeek 成本极低；设置每日调用上限 |
