# 产品战略 — 排课助手

> 版本：v1.1
> 日期：2026-05-15
> 定位更新：从"排课管理工具"升级为"教练成长助手"

---

## 一、核心定位

**帮兼职教练上更好的课。**

排课是入口，成长是价值。不是排课管理工具，不是会员 CRM。

---

## 二、产品哲学

### 少即是多

功能不必太复杂。做到极致才会有持续的客户。

- **MVP 的定义要澄清澄清再澄清** — 每个功能都要回答"这对教练上好课有直接帮助吗？"
- **不做"差不多能用"，做"一个功能惊艳"** — 宁可只有 3 个功能但每个都让人说"哇"
- **用户极致体验是底线** — 不能交付半成品去试水，半成品换来的不是反馈而是卸载
- **复杂度 = 流失率** — 每多一个按钮，就多一个教练放弃的理由

### AI 时代的成本纪律

**规模不能变成成本。** 每一次 AI 调用都有真金白银。

- AI 功能的成本必须在**培养用户习惯之前**算清楚
- 不能先免费铺量再发现"用户越多亏得越多"
- 每个 AI 功能要有明确的 **单次成本 × 预估频次 = 月成本** 计算
- 架构上预留降级能力：高峰期可降级到规则引擎，不依赖每次都调 LLM

---

## 三、目标用户

**兼职私人教练（瑜伽/普拉提/体能）**

- 带 3-10 个私教会员
- 正在快速成长期，渴望提升上课质量
- 当前用手机备忘录管理排课
- 有课后记录习惯（或愿意培养）
- 对自己有要求——这是核心客群筛选标准
- **价格敏感但认可真正的价值** — 不会为噱头付费，但会为"确实帮到我"买单

**不是**目标用户：
- 大型连锁健身房教练（有内部系统）
- 纯粹只想记个时间的"佛系"教练
- 工作室老板（管理需求不同）

---

## 四、核心数据飞轮

```
极简录课（替代备忘录）
    ↓ 积累数据
课后快速记录（30秒完成）
    ↓ 喂养 AI
AI 课前建议主动交付
    ↓ 教练成长
更愿意记录 → 数据更多 → 建议更准
```

飞轮的关键卡点：**录入摩擦**。如果录课比备忘录还麻烦，飞轮转不起来。

## 五、两个啊哈时刻

### 啊哈时刻 1：排课真好用

"我语音说了一句话，课就排好了。"

- 核心体验：自然语言/语音 → 结构化课程，一步到位
- 对比锚点：从备忘录切换过来，必须更快而不是更慢
- 衡量指标：新用户首次录课完成率、录课耗时 < 15秒
- **课表颜值是关键** — 好看到想截图发朋友圈、发给会员确认排课
  - 课表就是教练的"门面"，也是 App 的免费广告
  - 支持多风格主题，教练选择自己的"人设"
  - 截图友好：固定比例、边距舒适、品牌水印

### 啊哈时刻 2：高质量建议主动推送

"我打开 App，今天要上的课已经有建议了——该练什么、要注意什么。"

- 核心体验：不用我想，系统基于历史数据告诉我
- 对比锚点：以前靠脑子回忆上次练了什么
- 衡量指标：建议卡片查看率、教练采纳率

## 七、收费策略

### 核心原则

1. **在培养用户习惯之前把收费模型跑通** — 不能先免费铺量再补收费
2. **价格敏感但认价值** — 客群不为噱头付费，但会为"真帮到我"买单
3. **AI 成本不能随规模线性增长** — 需要成本上限设计

### 成本估算（单用户/月）

| AI 功能 | 频次假设 | 单次成本 | 月成本 |
|---------|---------|---------|--------|
| 自然语言录课 | 20次/月（每周5次） | ¥0.03 | ¥0.6 |
| 课后语音速记 | 15次/月 | ¥0.03 | ¥0.45 |
| 课前建议卡 | 15次/月 | ¥0.05 | ¥0.75 |
| **合计** | | | **¥1.8/月** |

> 注：以上为 DeepSeek/国产模型估算。Claude 约 3-5x 成本，仅用于 V2 高质量建议。

### 定价思路（待验证）

| 版本 | 价格 | AI 额度 | 目标 |
|------|------|---------|------|
| 免费版 | ¥0 | 排课+会员管理（无 AI） | 让教练先用起来，体验飞轮基础 |
| 成长版 | ¥9.9/月 或 ¥68/年 | AI 录课 + 课后速记 + 课前建议 | 核心付费点，覆盖 AI 成本 + 利润 |
| 按量包 | ¥1.9/10次 | AI 功能单次购买 | 低频用户，降低决策门槛 |

**关键设计：**
- 免费版功能完整但纯手动 — 不是阉割版，是"没有 AI 的完整工具"
- 付费解锁的是 AI 提效 — 教练能明确感知"AI 帮我省了多少时间"
- 按量包做试用钩子 — 先体验 10 次 AI，觉得值再订阅
- 年付优惠大 — 锁定长期用户，降低流失

### 成本红线

| 指标 | 红线 |
|------|------|
| 单用户 AI 月成本 | < ¥3（超过则降级到规则引擎） |
| AI 功能毛利率 | > 60%（定价必须覆盖成本 + 利润） |
| 免费用户 AI 成本 | ¥0（免费版不含 AI，零边际成本） |

## 八、竞争壁垒

不是"功能多"，而是"数据飞轮转起来后别人追不上"：

1. **录入极简** — 语音/文本秒录，比备忘录还快
2. **数据积累** — 用得越久，会员训练数据越完整
3. **AI 建议质量** — 数据越多，建议越准，形成正循环
4. **课表颜值** — 截图传播，教练自发推广

## 九、种子用户策略

```
核心体验官：你老婆（日常使用 + 即时反馈）
种子用户池：她的教练圈子（3-5人内测）
知识库审核：圈内资深教练
```

验证节奏：
1. 先让她用当前版本跑 1-2 周，收集"备忘录 vs 排课助手"的真实对比
2. 用访谈问题清单（见 AI-LESSON-PLAN.md）和她深聊
3. 自然语言录课做出来后，拉 3-5 人内测

## 十、技术栈对齐

| 层 | 选型 | 服务于 |
|----|------|--------|
| 小程序 | 原生 WXML/JS | 微信生态触达 |
| H5 | Vue3 + Vant 4 | 跨平台 + 分享链接 |
| 服务端 | Node.js Fastify | AI Agent + 业务 API |
| AI | LLM (DeepSeek 主力 / Claude 高级功能) | 语音解析 + 课前建议 |
| 存储 | MinIO/OSS | 照片资料 |

**架构原则：底层是 Agent（API + AI），上层是 UI 壳。**
- 服务端按 AI Agent + 业务 API 分层设计
- 小程序和 H5 都是瘦客户端
- 前端形态为"智能表单"而非"聊天窗口"—— AI 无感化
- 详见 `SERVER-DESIGN.md` 和 `FEASIBILITY-ANALYSIS.md`

## 十一、教练工作流（真实场景）

### 排课场景

```
每周日/周一：批量排下周课
    "张三周一周五3点，李四周二周三10点"
    → 一段话排 5 节课

中间穿插：零散补课
    "王姐想约周四下午，看看有没有空"
    → 查空闲 → 填入

临时变动：调课/取消
    "周三李四的课改到周四同一时间"
    → 快速调整
```

### 课后记录场景

```
场景 A — 即时速记（课后 social 时）
    和会员聊着天，顺手语音说一句
    "小林深蹲进步很大，但右膝代偿注意"
    → 30 秒完成，不打断社交

场景 B — 批量补录（连课结束后）
    连上了 3 节课，晚上统一录
    "第一节小林核心不错，第二节张姐腰伤注意，第三节团课到了 6 人"
    → AI 自动拆分到对应课程

场景 C — 发给馆方存档
    馆方要求教练提交会员情况
    → 从 App 导出结构化记录，一键发送
```

### 新会员体态评估场景

```
新会员首次到馆：
    1. 教练做体态评估（侧面/正面/背面拍照）
    2. 记录身体情况（头前引、悬垂腹等）
    3. 制定训练计划（呼吸模式→核心→脊柱→运动表现）
    4. 给出课程建议（私教20节/每周2-3次）
    → 评估报告存入会员档案，后续排课和 AI 建议都引用

详见 ASSESSMENT-TEMPLATE.md（真实馆方模板）
```
