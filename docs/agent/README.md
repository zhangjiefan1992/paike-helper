## 下一步要讨论的问题（按优先级）

> 这些问题会在多轮对话里逐步回答，每回答一个就更新到 PRD/WIREFRAME/DECISIONS。

1. **核心场景细化**
   - 教练真的会怎么用这个功能？什么情境点开？
   - "AI 备课建议"是用户主动触发，还是系统在课程开始前主动推送？
   - 跟现有的 aiDigest（每节课的客档）什么关系？
2. **输入形态**
   - 教练每次问询要不要选择"模式"（备课 / 评估 / 跟进 / 其他）？
   - 还是统一一个对话框，让 router agent 自动识别？
3. **输出形态**
   - 4 派输出永远展开还是默认折叠？
   - 用户看完综合建议 → 一键应用到下次课程的字段，怎么映射？
4. **多轮对话边界**
   - 同一会员的咨询，下次打开是新会话还是接续？
   - 跨会员的咨询能否引用？（"参考下王芳的案例"）
5. **失败兜底**
   - LLM 超时 / 输出垃圾 / 知识层缺失 → UI 怎么表现？
6. **成本预算**
   - 单次咨询愿意承担多少 token 成本？决定 wiki 大小、并行 agent 数

## 跟主产品（排课助手）的关系

- **完全是延伸功能**，不是独立产品
- 入口在会员详情页（教练翻看会员客档时自然触发）
- 共享数据：会员档案、近期课程、aiDigest
- 输出可以"应用回排课"（下次课程预填字段）
- 部署独立（Python + AgentScope on FC，子域名 ai.keleya.org）但用户感知是一体的
