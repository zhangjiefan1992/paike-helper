## 结构化分析

### 数据字段拆解

| 区块 | 字段 | 类型 | 说明 |
|------|------|------|------|
| **基本信息** | memberName | string | 会员姓名 |
| | managingCoach | string | 经管老师（负责日常管理） |
| | assessingCoach | string | 评估老师（做体态评估的人） |
| | assessmentDate | string | 评估时间 |
| | fitnessGoal | string | 运动需求（会员自述目标） |
| **评估结果** | bodyCondition | string | 身体情况诊断（如"头前引+悬垂腹"） |
| | recommendations | string | 评估后总体建议 |
| **训练方案** | manualTherapy | string | 手法参与（筋膜松解等） |
| | trainingPlan | string[] | 训练计划（分步骤目标列表） |
| | courseSuggestion | string | 课程建议（类型+总量+频次） |
| **体态照片** | sideView | photo[] | 侧面观（侧表链） |
| | frontView | photo[] | 正面观 |
| | backView | photo[] | 后面观（后表链） |
| | measurements | photo[] | 测量维度记录 |

### 关键洞察

1. **评估是一次性事件**：新会员入会时做一次，不是每节课都做
2. **评估驱动训练方案**：体态问题 → 训练目标 → 课程建议 → 排课依据
3. **照片是核心**：4 个角度的体态照片，用于记录基线和跟踪变化
4. **涉及多角色**：经管老师 ≠ 评估老师 ≠ 上课老师（但对于自由教练可能是同一人）
5. **专业术语密集**：头前引、悬垂腹、筋膜松解、三腔对位 — 这些是教练的专业语言

### 对产品的影响

- 体态评估应作为 **Member 的独立子模块**，不是 Session.notes
- 评估照片需要 **结构化存储**（按角度分类），不是混在课程照片里
- 训练计划是 **连接评估和排课的桥梁** — AI 课前建议可以引用评估结论
- 测量维度可以 **定期复评**，形成进展对比（这是会员续课的强有力证据）
