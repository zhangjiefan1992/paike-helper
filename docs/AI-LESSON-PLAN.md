# AI 课前建议 — 产品方案（预留）

> 版本：v0.1（方向探索）
> 日期：2026-05-15
> 状态：待用户访谈验证

---

## 一、定位

帮助教练（尤其新手教练）在课前快速获得结构化参考信息，提升备课效率和上课质量。

**不是**替代教练的专业判断，而是把散落的信息（历史课程、会员标签、备注）整合成一张"课前参考卡"。

---

## 二、核心交互模式

```
教练点"生成课前建议"
    ↓
POST /api/v1/ai/lesson-plan（异步任务）
    ↓
服务端 Claude 工作流执行（10-30s）
    ↓
结果存储，客户端轮询/推送拿结果
    ↓
展示"课前参考卡"，教练可采纳/忽略/微调
```

**关键设计：提交→交付模式**，不阻塞用户操作。教练提交后可以继续做其他事，结果好了再看。

---

## 三、V1 产物形态：结构化提醒卡

V1 不给具体动作编排（知识库质量不可控），只给基于事实数据的结构化提醒：

```
📋 王小明 · 课前参考
─────────────────────────
上次训练：5/13 下肢（深蹲、箭步蹲、桥式）
本次建议：重点可转向上肢/核心（间隔恢复）
⚠️ 注意：腰伤标签 — 避免高负荷脊柱屈曲
📊 近4次训练分布：下肢3次、核心1次 → 上肢较少
💡 会员备注：上次记录"右膝轻微不适"
```

**80% 靠结构化数据**（历史课程、标签、备注），**20% 靠 AI 串联表达**。质量可控，因为事实来自教练自己录入的数据。

### V1 → V2 升级路径

| 版本 | 产物 | 知识库依赖 | 风险 |
|------|------|-----------|------|
| V1 | 结构化提醒（训练分布、注意事项、会员备注） | 无，纯数据驱动 | 低 |
| V2 | 部位/方向建议（"建议练核心，搭配平衡训练"） | 通用训练原则 | 中 |
| V3 | 动作编排建议（"做死虫子而非仰卧起坐"） | 专业动作库 | 高，需专业审核 |

---

## 四、输入数据

| 数据 | 来源 | 说明 |
|------|------|------|
| 会员基本信息 | Member 档案 | 姓名、标签（腰伤、新手、VIP） |
| 历史课程记录 | Session 列表 | 日期、课程类型、训练重点、状态、备注 |
| 会员备注 | Member.notes | 自由文本，教练记录的特殊情况 |
| 课程备注 | Session.notes | 每次课后的反馈记录 |
| 训练分布统计 | 计算得出 | 近 N 次课的部位/类型分布 |

### 暂不纳入（V1）

- 外部知识库（训练原则、动作库）— 质量无法保证
- 体态评估数据 — 需要额外采集手段
- 照片分析 — 技术复杂度高

## 五、技术方案

### 5.1 API 设计

```
POST /api/v1/ai/lesson-plan
  请求: {
    memberId: string,
    sessionDate: string,       // 计划上课日期
    courseType?: string         // 预选的课程类型（可选）
  }
  响应: { taskId: string, status: "processing" }

GET /api/v1/ai/lesson-plan/:taskId
  响应: {
    status: "processing" | "completed" | "failed",
    result?: {
      summary: string,           // 一句话总结
      lastSession: {...},        // 上次课程信息
      focusSuggestion: string,   // 建议训练重点
      warnings: string[],        // 注意事项（基于标签和备注）
      distribution: {...},       // 近期训练分布
      memberNotes: string        // 会员特殊备注
    }
  }
```

### 5.2 服务端工作流

```
1. 收到请求 → 查会员档案 + 近 10 次课程记录
2. 组装 prompt（固定模板 + 结构化数据）
3. 调 LLM（Claude/DeepSeek）→ 生成建议
4. 结果结构化存储 → 标记任务完成
5. 客户端拉取展示
```

Prompt 模板核心：
- system: "你是一位普拉提/瑜伽训练顾问，根据会员历史数据给出简洁的课前参考建议。只基于提供的数据，不编造信息。"
- user: 结构化的会员数据和历史记录

### 5.3 客户端入口

会员详情页 → "生成课前建议" 按钮 → 展示建议卡片

或：课程表单编辑时 → 侧边快捷入口 → 参考建议后填写训练重点

## 六、用户访谈问题清单

在实现前需验证以下假设：

### 痛点验证

1. "你备课花多长时间？新会员 vs 老会员分别多久？"
   → 验证备课是否真的是痛点，还是教练凭经验秒决策

2. "你怎么决定今天给这个会员练什么？脑子里过一遍？还是有笔记参考？"
   → 了解真实决策路径，AI 替代的是哪个环节

3. "有没有遇到过'这个会员上次练了什么我忘了'的情况？多久一次？"
   → 验证"历史记录参考"这个需求的频率

### 方案验证

4. "如果系统给你一个建议：'本次建议重点练核心，避免深蹲（腰伤标签）'，你觉得有用吗？会看吗？"
   → 直接验证产物形态是否有价值

5. "你更希望建议具体到动作（比如'做死虫子而不是仰卧起坐'），还是只给方向（比如'练核心'）？"
   → 决定知识库需要多深、产物粒度

6. "你会不会觉得这种建议是对你专业能力的质疑？"
   → 心理接受度，措辞很重要——"参考建议"不是"教你上课"

### 知识库边界

7. "你上课的动作编排，主要靠培训体系（比如 BASI/Balanced Body）还是自己经验？"
   → 判断通用知识库能覆盖多大比例

8. "不同流派的教练，训练理念差异大吗？同一个腰伤会员，方案可能完全不同？"
   → 如果差异大 → AI 只给"安全底线"建议（避免什么），不给"应该做什么"

---

## 七、决策要点

- **V1 只做数据驱动**，不依赖外部知识库，降低质量风险
- **建议是"参考"不是"指导"**，UI 措辞要柔和，尊重教练专业性
- **异步执行**，不阻塞用户主流程
- **先做预留**，等自然语言录入（parse-text）和语音能力跑通后，作为核心增值功能推出
