## Context

当前项目是微信开发者工具生成的默认小程序模板，包含 `pages/index/` 和 `pages/logs/` 两个占位页面。需要将其重构为完整的排课管理应用。

技术约束：
- 微信小程序原生开发（JS + WXML + WXSS），不使用第三方框架
- 组件框架使用 glass-easel
- 不依赖任何后端服务或云开发
- 本地存储上限 10MB（`wx.setStorageSync`）
- AppID（测试号）：`wxec7783fbf92910fd`

产品约束：
- 目标用户为 20-40 岁女性健身教练
- "动漫暖系"视觉风格，柔和、温暖、圆润
- 第一版为教练个人自用工具，不含社交/协作功能

## Goals / Non-Goals

**Goals:**
- 建立完整的本地数据层，支持会员、课程、配置的 CRUD 操作和数据导入导出
- 实现周视图 + 日视图双层排课视图，让教练一眼看清排课全貌
- 实现课程录入/编辑全流程，支持私教和团课两种模式
- 实现会员管理与上课时间轴，追踪会员练习历史
- 建立 CSS 变量主题系统，预留多主题扩展能力
- 实现数据 JSON 导出/导入备份恢复

**Non-Goals:**
- 会员端自助预约功能
- 课时费 / 财务统计
- 微信消息通知推送
- 多教练协作
- 云端数据同步
- 多主题切换实际功能（仅预留架构入口）

## Decisions

### D1: 原生开发，不使用 Taro/uni-app 等跨端框架

**选择**：微信小程序原生 JS + WXML + WXSS

**理由**：项目仅面向微信平台，无跨端需求；原生开发零依赖、无构建步骤、调试直接；glass-easel 组件框架已提供足够的组件化能力。

**替代方案**：Taro（引入 React 依赖和构建复杂度，对单平台项目过重）、uni-app（Vue 生态，同样过重）。

### D2: 纯本地存储，单 JSON 数组方案

**选择**：三个 Storage Key（`pk_members`、`pk_sessions`、`pk_config`），每个存储完整的 JSON 数组。

**理由**：数据规模小（个人教练场景，数千条记录约占 1-2MB），读写操作简单直接；无需分片或索引机制。全量读写在此数据规模下性能完全可接受（< 100ms）。

**替代方案**：按月/按日分片存储（增加查询复杂度，收益不大）；使用小程序本地数据库（API 复杂度高，不适合简单场景）。

### D3: 页面间数据刷新策略使用 onShow 重新加载

**选择**：列表页和视图页在 `onShow` 生命周期中从 Storage 重新加载数据。

**理由**：简单可靠，无需实现事件总线或全局状态管理；数据量小，重新加载无性能负担；确保从编辑/详情页返回时数据始终最新。

**替代方案**：全局事件总线（EventBus 需维护订阅关系，增加复杂度）；globalData 共享状态（需手动同步，容易遗漏）。

### D4: 主题系统使用 CSS 自定义属性（CSS Variables）

**选择**：在 `app.wxss` 的 `page` 选择器中定义全局 CSS 变量，所有页面和组件通过 `var()` 引用。

**理由**：原生支持、无运行时开销；切换主题只需覆盖变量值；小程序基础库 2.25.0+ 完全支持 CSS Variables。

**替代方案**：WXSS 预处理（无法动态切换）；JS 动态设置 style（性能差、代码臃肿）。

### D5: 课程卡片左滑操作使用 movable-view 实现

**选择**：使用 `movable-area` + `movable-view` 组合实现课程卡片的左滑露出快捷操作按钮。

**理由**：原生组件性能好；支持 `damping` 和 `friction` 参数调节手感；已有成熟的实现模式。

**替代方案**：`scroll-view` 横向滚动（难以精确控制停靠位置）；touch 事件手动实现（需处理与页面滚动的冲突）。

### D6: 照片仅存储临时路径引用

**选择**：课程照片存储 `wx.chooseMedia` 返回的临时文件路径，不做 base64 编码。

**理由**：10MB 存储限制下，base64 编码的照片会迅速耗尽空间；临时路径在小程序生命周期内有效；提示用户将原图保存到相册。

**已知限制**：临时路径在小程序清除缓存后失效，照片会丢失。用户需自行保存原图。

### D7: 7 列周视图使用 flex 等宽布局

**选择**：周视图 7 天使用 `display: flex` 等宽列布局，每列内纵向排列课程卡片。

**理由**：布局简单直观；在各尺寸屏幕上自适应良好；课程卡片超过 3 条时折叠显示 "+N" 避免 DOM 过多。

**替代方案**：scroll-view 横向滚动（破坏一眼看全周的体验）；grid 布局（flex 已足够，grid 增加复杂度）。

## Risks / Trade-offs

**[临时路径照片丢失]** → 在设置页和照片相关操作处提示用户"照片仅缓存预览，请自行保存原图到相册"。后续版本可考虑使用 `wx.getFileSystemManager().saveFile()` 持久化。

**[10MB 存储上限]** → 当前数据模型为纯文本，数千条记录约 1-2MB，风险低。在数据导出时显示当前已用存储量，让用户有感知。

**[测试号 API 限制]** → `wx.shareFileMessage` 等 API 在测试号下可能受限。开发阶段用 `console.log` 验证数据，正式发布前切换为注册的正式 AppID。

**[无数据同步]** → 换手机或卸载小程序会丢失数据。通过导出/导入功能缓解，在设置页显著提示"定期备份"。
